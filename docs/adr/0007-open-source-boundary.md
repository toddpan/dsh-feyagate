# ADR-0007：开源边界 —— 仓库不含二进制、口径写进 NOTICE、专有库永不分发

> **这个文件解决什么问题**：回答"这个 MIT 仓库里到底有什么、没有什么"，以及"下载来的二进制和小米专有库在许可上怎么处理、哪些是我们**不知道**的"。

- **Status**：Accepted
- **Date**：2026-09-25
- **相关**：[`NOTICE`](../../NOTICE)、[`LICENSE`](../../LICENSE)、[ADR-0004](0004-binary-upgrade.md)、[ADR-0002](0002-install-directory.md)

---

## Context

本插件的功能依赖一个**闭源二进制** `miloco-mcp-server`（C++ 常驻服务，`--config <path>` 启动，`POST /mcp/http` 是 MCP Streamable HTTP 端点，`GET /health` 是健康检查）。它由权利人（`toddpan/miloco-mcp-server-releases` + 自有 FOTA `oneapi.sooncore.com`）发布多平台产物。

三方事实让"边界"必须显式写下来：

1. **产物里含一个小米专有组件**：`lib/libmiot_camera_lite.{dylib,so}`（摄像头 P2P 流），版权属小米。部分上游构建**不含**它。
2. **许可证口径本身是模糊的**：
   - 上游源码树带一个 MIT 许可证文件；
   - README 又写明 "Based on the Xiaomi Miloco project. Camera native library is proprietary to Xiaomi"；
   - 也就是说，**"闭源"是分发策略，不是许可证结论**；
   - 上游基于 Xiaomi Miloco 项目，**其上游血统的许可证没有在本项目内被审计过**。
3. **Linux 产物是动态链接的**：声明的运行时依赖包含 `libssl3` / `libyaml-cpp0.7` / `libfmt8` / `libcpp-httplib0` / `libavcodec58` 等。若产物内捆绑了 LGPL 组件（例如 FFmpeg 系列），再分发需要满足 LGPL 的可重链接要求。

同时，npm 包的体积与"发布产物"的本能会把二进制拉进仓库 —— 必须有一条明确的规则挡住它。

## Decision

### 1. 仓库与 npm 包里没有任何二进制

| 类别 | 决定 |
|---|---|
| 插件源码（Host + 浏览器半侧）、`config.yaml` 模板、清单、ADR/文档、构建脚本 | ✅ 全部开源，MIT |
| `miloco-mcp-server` 的可执行文件、压缩包、裸 exe、deb/rpm/pkg、以及它的**任何一部分** | ❌ **不进仓库、不打进 npm 包、不出现在任何 release 附件** |
| 二进制镜像 | ⚠ 只能在**权利人自己的渠道**（现有 FOTA 就是）；社区 fork 必须指向自己的渠道，不得以本项目名义发布镜像 |

`package.json` 的 `files` 白名单只含 `lib`、`cordis.patch.yml`、`manifest`、`skills`、`README.md`、`NOTICE` —— **没有**任何存放二进制的目录。运行时下载落在**用户自己的机器**上（`~/.dsh/dsh-feyagate/versions/<ver>/`，见 [ADR-0002](0002-install-directory.md)），不经过本项目。

### 2. 口径写进 `NOTICE`，而不是只在 README 里提一句

[`NOTICE`](../../NOTICE) 必须包含五节，缺一不可：

1. **本仓库不含二进制**：明确"源码、清单与文档；不包含、不捆绑、不镜像、不再打包 `miloco-mcp-server` 或其任何部分"。
2. **运行期行为**：从权利人运营的渠道下载 → 按 `manifest/server-manifest.json` 校验 → 装进用户自己的机器；**本项目不分发该二进制，也不授予任何相关权利**。
3. **二进制的许可由它自己的渠道决定**，与本项目的 MIT 无关；本项目不对其作任何陈述。想再分发二进制或运营镜像的人，必须自行满足权利人条款；社区 fork 不得以本项目名义发镜像（下载源可配置，fork 应指向自己的渠道）。
4. **小米专有库永不分发**：`lib/libmiot_camera_lite.{dylib,so}` 不下载、不镜像、不捆绑、不再分发。上游部分构建不含它 → 摄像头不可用、其它平台正常，插件把这种情况显示为**"降级运行 + 原因"**，而不是静默失败或假装功能存在。
5. **上游归属与未审计声明**：署名上游自述基于 Xiaomi Miloco 项目、源码树带 MIT 许可证文件；产物可能带上第三方许可义务（含 Linux 上动态链接的 FFmpeg 系列），**这些义务属于发布产物的人，本项目不做审计**。若你是权利人并希望更正表述，请开 issue。

### 3. 插件自己的许可证是 MIT

`LICENSE` 是标准 MIT，版权行 `Copyright (c) 2026 FeyaGate Contributors`。**MIT 只覆盖本仓库的源码与文档**，不覆盖运行时下载的二进制 —— `NOTICE` 与 README 的 License 段都写明这一点，避免读者把两者混为一谈。

### 4. 代码层面同样遵守边界

- 清单里**不记录**小米专有库的任何 URL；下载器**没有**获取它的代码路径。
- 摄像头不可用时，界面呈现的是**降级 + 原因**（缺 `libmiot_camera_lite` 或平台不支持），不是"功能不存在"。
- 插件只访问清单与下载源里写明的地址（GitHub Releases / FOTA / 用户配置的镜像 / 本地文件），不去别的域名"找找看"。

## Consequences

**得到：**

- 仓库可以公开托管（含 CI、镜像、npm publish）而不承担再分发责任。
- 用户下载到的东西有明确出处与校验和（[ADR-0004](0004-binary-upgrade.md)），"信任"落在可核验的字节上而不是落在插件的善意的承诺上。
- 法务上的模糊之处被**如实写出**（而不是被含糊措辞掩盖），权利人若要更正有明确的入口。

**付出：**

- 首次安装必须联网（离线用户要用"本地包"这条降级路径）。
- 读者可能觉得"一个智能家居插件却不含二进制"很别扭 —— 所以 `NOTICE` 与 README 都必须在显眼处解释"为什么不含"。
- 上游若改变渠道或命名，需要维护清单（这是 [ADR-0004](0004-binary-upgrade.md) 的既有代价）。

## Alternatives

### 把二进制放进 GitHub Release 附件或 npm 包

- **否掉的原因**：① 那等于由本项目再分发一个闭源、且内含小米专有库的产物，责任与许可义务都落到本项目头上；② 上游自己已经在发布，重复分发只会制造版本分裂；③ npm 包的体积与"包含可执行文件"的审查风险都会上升。

### 直接依赖既有的 `feyagate-skill`（PyPI）或 `feyagate-desktop`

让用户先装 Python CLI 或 Electron 应用，插件复用其安装好的二进制。

- **否掉的原因**：安装链变长（用户要先装 Python 包）、既存安装的目录与端口会与本插件冲突（三条真实故障见 [ADR-0002](0002-install-directory.md)）、且插件的升级/回滚无法作用到别人管理的目录。**保留为只读探测 + attach 提示**，不做硬依赖。

### 干脆不显示摄像头功能（因为专有库可能缺失）

- **否掉的原因**：上游部分构建**包含**该库，摄像头在 macOS / Linux 上确实可用。把可用功能藏起来对用户是损失。正确做法是**尝试 + 如实降级**：能用就用，不能用就说清原因（缺哪个库、平台不支持、还是米家未登录）。

### 在 README 里下结论说"上游是 MIT，可以随意再分发"

- **否掉的原因**：这是一个**未经审计的推断**。上游源码树有 MIT 文件 ≠ 发布产物是 MIT（还涉及专有原生库、可能的 LGPL 动态链接、以及上游血统）。**不确定的事写成"未核实/待确认"**，不能为了让文档好看而升级成断言。这也是本 ADR 把"未审计"写进 `NOTICE` 的原因。

## 待确认

- 上游血统（Xiaomi Miloco 项目）的许可证：**未核实**。这是最高优先级的法务待办，需要权利人提供事实。
- Linux 产物是否捆绑 LGPL 组件、是否需要满足可重链接要求：**未审计**。打包清单需逐项审计后才可能有结论。
- 社区 fork 使用本项目名义发镜像时的处理方式：当前只有 `NOTICE` 里的**声明**，没有技术强制手段（下载源可配置本是特性）。是否需要额外机制（例如文档层面要求改名）由维护者决定。
